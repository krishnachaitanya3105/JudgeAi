## 🚀 Quick Start Path

```
1. Create .env file (5 min)
   ├─ Get SUPABASE_URL, SUPABASE_KEY
   ├─ Get GROQ_API_KEY
   └─ Create .env with these

2. Setup Backend (5 min)
   ├─ python -m venv venv
   ├─ venv\Scripts\activate
   └─ pip install -r requirements.txt

3. Setup Frontend (3 min)
   ├─ cd frontend
   └─ npm install

4. Start Servers (2 min)
   ├─ Terminal 1: uvicorn backend.main:app --reload
   └─ Terminal 2: npm run dev

5. Setup Supabase (10 min)
   ├─ Create project at supabase.com
   ├─ Run db_schema.sql in SQL editor
   └─ Create storage bucket "court-judgments"

Total: 25 minutes to production!
```

## 💾 API Endpoints (8 Total)

```
UPLOAD & EXTRACTION
  POST /api/upload-pdf                (with file + uploaded_by)
  POST /api/extract-actions           (with pdf_url)

VERIFICATION
  POST /api/approve-action/{id}       (with approved_by)
  POST /api/edit-action/{id}          (with field updates)
  POST /api/reject-action/{id}        (with rejection_reason)

DASHBOARDS
  GET /api/officer-dashboard          (optional: department)
  GET /api/admin-dashboard            (no params)
  GET /api/cases                      (skip, limit, status, dept)
```

All documented at http://localhost:8000/docs

## 📊 Database Design

### 6 Tables
1. **users** (Officer/admin accounts)
2. **cases** (Uploaded PDF metadata)
3. **extracted_actions** (AI results)
4. **audit_logs** (Change tracking)
5. **verification_queue** (Workflow)
6. **notifications** (User alerts)

### Indexes (10+)
- On case_number, status, department
- On deadline, created_at, confidence
- For fast filtering and sorting

### RLS Policies (6+)
- Officers see only their department
- Admins see all
- Users see only their own notifications

### Triggers (3)
- auto_update_timestamp on tables
- Enforce data consistency

## 🔄 Data Flow Example

```
User Action: Upload PDF
    │
    ▼
Frontend: UploadCard receives file
    │
    ▼
API Call: POST /upload-pdf
    │
    ▼
Backend: upload.py
    └─► Validate file
    └─► Store in Supabase Storage
    └─► Save metadata to 'cases' table
    └─► Return pdf_url + case_number
    │
    ▼
Frontend: Show success, trigger extraction
    │
    ▼
API Call: POST /extract-actions
    │
    ▼
Backend: extract.py
    └─► Download PDF from url
    └─► Extract text (PyMuPDF or OCR)
    └─► Send to Groq LLaMA3
    └─► Parse structured response
    └─► Save to 'extracted_actions' table
    └─► Log to 'audit_logs'
    │
    ▼
Frontend: Display results with confidence score
    │
    ▼
Officer Reviews
    └─► Click Approve / Edit / Reject
    │
    ▼
API Call: POST /approve-action/{id}
    │
    ▼
Backend: verification.py
    └─► Update status
    └─► Log to 'audit_logs'
    │
    ▼
Database: Updated with audit trail
    │
    ▼
Dashboard: Reflects new stats immediately
```
