JudgeAI - Cursor Analysis and Feature Inventory
Generated: 2026-05-02

============================================================
1) PROJECT OVERVIEW
============================================================
JudgeAI is a full-stack legal workflow platform that:
- accepts court judgment PDF uploads,
- extracts structured legal actions with Groq LLaMA,
- supports human verification (approve/edit/reject),
- tracks all review actions through audit logs,
- provides role-based dashboards for officer and admin users.

Stack:
- Backend: FastAPI + Supabase (PostgreSQL + Storage)
- Frontend: React (Vite) + Tailwind + React Router
- Charts: Recharts
- AI: Groq LLaMA extraction pipeline


============================================================
2) BACKEND FEATURES
============================================================
2.1 API Application
- FastAPI app entry in backend/main.py
- CORS enabled for local frontend origins
- Router modules mounted under /api

2.2 Configuration
- Environment loading via python-dotenv in backend/config.py
- Supports:
  SUPABASE_URL
  SUPABASE_KEY
  SUPABASE_STORAGE_BUCKET
  GROQ_API_KEY
- Singleton Supabase client helper

2.3 Upload Pipeline
Endpoint: POST /api/upload-pdf
- Validates PDF file type
- Uploads to Supabase storage bucket
- Generates case number
- Stores case metadata in cases table
- Returns public file URL and metadata

2.4 PDF Parsing
Service: backend/services/pdf_parser.py
- Primary extraction using PyMuPDF
- OCR fallback using EasyOCR if text is insufficient
- Supports extraction from path and URL

2.5 LLM Extraction
Endpoint: POST /api/extract-actions
Service: backend/services/llm_extractor.py
- Sends extracted text to Groq model
- Enforces JSON-only parsing strategy
- Extracts:
  case_number
  judgment_date
  department
  deadline
  directive
  confidence_score
  source_sentence
- Stores results in extracted_actions table with pending status

2.6 Verification Workflows
Endpoints:
- POST /api/approve-action/{id}
- POST /api/edit-action/{id}
- POST /api/reject-action/{id}

Behavior:
- approve -> status=approved + audit log
- edit -> status=edited + field updates + human_verified_values snapshot + audit logs
- reject -> status=rejected + rejection reason + audit log

2.7 Audit Logging
Utility: backend/utils/audit_logger.py
- reusable log_audit_event()
- per-case timeline retrieval
- aggregate stats helper

2.8 Deadline Engine
Utility: backend/utils/deadline_helper.py
- calculate_deadline_remaining()
- priority levels: urgent, warning, normal, overdue
- imminent-deadline helper for dashboards

2.9 Dashboards API
Officer endpoint: GET /api/officer-dashboard
- pending/approved/completed counts
- urgent deadlines count
- recent uploads
- optional department filter

Admin endpoint: GET /api/admin-dashboard
- total cases
- status distribution
- deadline alerts
- department stats
- verification counts
- recent audit activities
- verification trend data (7-day buckets)
- cases processed per department summary

2.10 Cases APIs
- GET /api/cases with pagination and filters:
  status, department, case_number
- GET /api/cases/{action_id}:
  full extracted action + deadline info + audit logs

2.11 Database Schema and Security
Schema file: backend/db_schema.sql
- tables: users, cases, extracted_actions, audit_logs, verification_queue, notifications
- indexes for key query paths
- RLS policies for role/department scoping
- updated_at triggers and dashboard views

2.12 Auth/User Seeding Script
Script: backend/scripts/seed_supabase_users.py
- creates Supabase auth users:
  admin@judgeai.local / admin123
  officer@judgeai.local / officer123
- upserts role profiles in public.users
- uses SUPABASE_SERVICE_ROLE_KEY (or SUPABASE_KEY fallback)
